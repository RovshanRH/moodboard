# Отчёт по практической работе № 9

## 4. Доработка индивидуального проекта

В проекте «Mood board creator» выполнен переход от прямого доступа к SQLite
через `sqlite3` и SQL-запросы к работе с данными средствами Django ORM.

Описаны следующие модели:

- `Designer` — профиль дизайнера: `user`, `display_name`, `bio`;
- `Client` — заказчик: `user`, `name`, `email`, `company`;
- `MoodboardCatalog` — каталог дизайнера: `designer`, `name`,
  `description`;
- `Moodboard` — мудборд: `designer`, `catalog`, `client`, `title`,
  `description`, `background_color`, `palette`, `created_at`, `updated_at`.

Между моделями настроены связи Django ORM. Профиль дизайнера связан со
стандартным пользователем посредством `OneToOneField`. Каталог и мудборд
связаны с дизайнером через `ForeignKey`. Мудборд может иметь каталог и
заказчика; для этих связей используется `ForeignKey` с `SET_NULL`, поэтому
удаление необязательного связанного объекта не удаляет сам мудборд.
Для каталога добавлено ограничение уникальности имени в пределах одного
дизайнера.

Для управления структурой базы данных используются миграции Django:
`accounts.0001`, `catalogs.0001`, `boards.0001`, а также миграции приложения
`moodboards` с изменением палитры, связи клиента и удалением старых моделей
из состояния миграций. Исторические таблицы проекта сохранены через
`SeparateDatabaseAndState`, а актуальные модели зарегистрированы в приложениях
`accounts`, `boards` и `catalogs`.

Выбрана стратегия сохранения существующей структуры таблиц с переходом
прикладного кода на Django ORM. Основной базой проекта является `db.sqlite3`.
Для переноса данных реализована команда
`python manage.py import_data <username> --file <path>`. Она загружает JSON,
создаёт или обновляет клиентов и каталоги, а затем импортирует мудборды с
восстановлением связей. Обратная выгрузка выполняется командой
`python manage.py export_data <username>`.

Через ORM реализованы операции создания, чтения, фильтрации, сортировки,
агрегации и получения связанных объектов. Методы `select_related`, `filter`,
`values`, `annotate`, `aggregate`, `Count` и `Coalesce` используются для
получения связанных данных и статистики без ручных SQL-запросов.

Адаптированы представления и страницы:

- главная страница и подсчёт количества мудбордов;
- список мудбордов;
- детальная страница мудборда с обработкой 404;
- поиск по названию;
- агрегированная статистика;
- списки каталогов и заказчиков с количеством связанных мудбордов.

API, авторизация, создание мудбордов, экспорт PNG и пользовательские URL
сохранены. Обновлён `README.md`: в нём описаны модели, связи, миграции,
порядок запуска и перенос данных.
