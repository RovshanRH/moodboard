# Практическая работа № 11. Django Forms

## 1. Тема и цель работы

Тема: работа с формами в Django для индивидуального проекта Moodboard creator.

Цель: освоить создание, обработку, валидацию и отображение форм, а также добавить загрузку и отображение изображений в веб-приложении с сохранением текущей архитектуры проекта.

## 2. Краткое описание выполненных заданий Яндекс Практикума

В ходе практической работы были изучены и применены базовые принципы работы с веб-формами:

- обработка GET- и POST-запросов;
- создание форм на основе класса `forms.Form` и `ModelForm`;
- передача формы в шаблон и отображение полей, ошибок и подсказок;
- серверная валидация пользовательского ввода;
- сохранение данных только после успешной проверки;
- защита POST-запросов CSRF-токеном;
- работа с медиафайлами и изображениями в форме.

В проекте всё это адаптировано под сущности Moodboard creator: дизайнеры, каталоги, заказчики и мудборды.

## 3. Описание настроек форм и их интеграции в Django

Для проекта были созданы формы, соответствующие предметной области:

- `MoodboardForm` — `ModelForm` для создания и редактирования мудбордов;
- `MoodboardSearchForm` — форма для фильтрации и поиска по названию.

Форма настроена так, чтобы:

- ограничивать выбор каталога только каталогами текущего дизайнера;
- приводить палитру к списку HEX-цветов;
- валидировать формат цвета и обязательные поля;
- принимать `request.FILES` и сохранять загруженные изображения;
- использовать общие Bootstrap-стили и подставлять подсказки для пользователя.

Шаблон формы переведён на рендеринг через Django `form`-объект, включая отображение ошибок и подсказок. Это позволяет отделить описание полей, валидацию и шаблонную разметку.

## 4. Изменения моделей, миграций и шаблонов

В модели `Moodboard` добавлено поле `image` типа `ImageField` с загрузкой в папку `media/moodboards/`.

Изменения затронули:

- `boards/models.py` — добавлено поле `image`, обновлён метод `to_data()`;
- `boards/forms.py` — создана форма для ввода и поиска;
- `boards/views.py` — переведён процесс создания и редактирования мудборда на `ModelForm`; добавлены страницы редактирования и удаления;
- `boards/urls.py` — добавлены маршруты для `edit` и `delete`;
- `config/settings.py` и `config/urls.py` — настроены `MEDIA_URL`, `MEDIA_ROOT` и отдача медиафайлов в режиме разработки;
- `moodboards/templates/moodboards/moodboard_form.html` — форма рендерится через Django-форму;
- `moodboards/templates/moodboards/moodboard_detail.html` — добавлено отображение изображения;
- `moodboards/templates/moodboards/search.html` — поиск переведён на Django `Form`.

Для обновления схемы добавлены миграции:

- `boards/migrations/0002_moodboard_image.py` — совместимость с текущей историей проекта;
- `moodboards/migrations/0005_moodboard_image.py` — добавление поля `image` в реальную схему данных.

## 5. Проверка валидации, поиска, редактирования и загрузки файлов

Проверены следующие сценарии:

- создание мудборда через форму;
- редактирование существующего мудборда;
- удаление через POST с CSRF-защитой;
- валидация пустого названия и некорректного цвета;
- поиск по строке `q` через `MoodboardSearchForm`;
- загрузка изображения и его отображение на карточке и на странице деталей;
- отображение ошибок формы без необработанных исключений.

## 6. Результаты проверки доступности и применения бизнес-правил

Сохранены существующие правила предметной области:

- каталог выбирается только среди каталогов текущего дизайнера;
- при попытке назначить чужой каталог форма или логика не допускают некорректный ввод;
- данные сохраняются только после успешной валидации формы;
- изображения хранятся как отдельные медиафайлы, а не как статические ресурсы проекта.
